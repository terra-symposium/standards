# Terra Cloud Playwright

This repository-specific extension adds Terra Symposium's environment and suite requirements to the shared `cloud-playwright` skill. Follow the shared skill for allowance, account, task-control, repository-access, and executor/network preflight rules. Use this skill only for a task attached to the published `terra-symposium-test-fixing` environment and `Terra-Symposium/terra-symposium-website` repository.

1. Inspect `/workspace` and its immediate child directories for `.git` directories or files. Locate the repository containing `scripts/test/cloud-checkout.mjs`, then run that verifier with `/workspace`, the requested branch, and the expected SHA when one was supplied. Require exactly one matching checkout and use its directory for all commands. Read its `AGENTS.md` if present and `.codex/environments/terra-symposium-test-fixing.json`. From the verified checkout, source `scripts/setup/cloud-runtime.sh`, run `terra_cloud_verify_tools`, then run `node scripts/setup/cloud-installation.mjs verify`. This uses the published `/workspace/.terra-tools` installation. If the lockfile changed, rerun the frozen install and browser installation before writing a new receipt. Confirm the local environment name and `TERRA_CODEX_CLOUD=1` after the shared skill's task and checkout gate passes.
2. After the shared executor and network-policy checks pass, run `pnpm run test:cloud-diagnostic` before Git fetches or Infisical. This command makes a bounded HTTPS request through the inherited proxy and reports network errors separately from HTTP status. A proxy URL or a stale revision label is not proof of readiness. If this probe fails, stop and record the task URL, bound environment identity/revision, and sanitized error; do not retry an unchanged setup or bypass the proxy. Cloud commands bootstrap Node fetch through the inherited proxy; Playwright uses explicit browser proxy settings with loopback bypass only.
3. For the standard shared-development suite, require the exact Neon development endpoint and a ready Infisical network-secret binding. Cloud PostgreSQL uses Neon's secure WebSocket driver through the HTTPS proxy; do not start the Tailscale relay or request a raw TCP grant. Then run `pnpm run setup:verify` and `pnpm run test:cloud-preflight`. Preflight fetches `SANITY_STUDIO_TEST_TOKEN` dynamically from Infisical Development for the test-only delivery scope, requires `SANITY_STUDIO_TEST_USER_ID`, matches that ID against the token's `/users/me` identity, verifies project access, creates task-scoped app and Studio states, and verifies database/browser readiness. Never provision or require stored `PLAYWRIGHT_*_AUTH_STATE` values. When task-local isolation is requested or Neon is unreachable and the task needs database-backed browser coverage, run `pnpm run test:cloud:disposable`. It starts a fresh in-memory PostgreSQL-compatible PGlite server on loopback, creates the declared app schema in that empty database, serializes workers, and then uses the same auth, service, browser, inventory, viewport, and cleanup path as the standard suite. This mode requires the runtime Sanity Studio identity and Cloud proxy access; it does not test Neon transport, Neon-only behavior, or development data. The disposable database shuts down when the command exits.
4. For full disposable coverage, run `pnpm run test:cloud:disposable` with no filters and unset `PW_VIEWPORTS`. It collects every configured project and runs all six standard viewports through the same orchestration. The shared-development alternative is `pnpm run test:cloud -- <optional Playwright arguments>` only when that database is authorized. Never replace Cloud orchestration with a direct `playwright test` command.
5. When a fast verdict is explicitly requested, run `pnpm run test:cloud:smoke`. This delegates to the disposable wrapper with `PW_VIEWPORTS=desktop`, one Chromium project (`cloud-smoke`), one worker, and four checks: fresh loopback database/schema readiness, public landing route, authenticated application session route, and matching Sanity user identity with project access. It does not exercise the Studio UI, Docs editing, generation, or the complete responsive inventory. A passing smoke never replaces full coverage. The equivalent supported filter command is:

   ```sh
   PW_VIEWPORTS=desktop PW_WORKERS=1 TERRA_CLOUD_RESULT_DIR=test-results/cloud-smoke \
     pnpm run test:cloud:disposable -- \
     --config=scripts/test/playwright.cloud-smoke.config.ts \
     --project=cloud-smoke --grep=cloud.smoke. --workers=1
   ```

6. Review `test-results/cloud/manifest.json` for full runs or `test-results/cloud-smoke/manifest.json` for smoke runs. Add the selected project counts and viewport evidence to the report required by the shared `cloud-playwright` skill.

## Evidence and cleanup

- Include the live environment revision in the local suite evidence; do not substitute a stale configured label. Preserve inherited proxy and CA trust.
- The wrapper reloads Development credentials for each invocation. Both Studio keys are test-only deliveries; no static `PLAYWRIGHT_*_AUTH_STATE` is used. Identity mismatch, denied project access, or missing credentials are blockers, never passing skips.
- Missing-token partial coverage is opt-in only: `TERRA_CLOUD_ALLOW_MISSING_STUDIO=1 pnpm run test:cloud:disposable`. It excludes the Studio and generation projects, lists their blocked counts, and returns failure for incomplete coverage. It accepts no extra filters and still runs the app projects at all six viewports. Use this only when explicitly requested; smoke requires both Studio keys.
- The manifest records selected inventory, executed/passed/failed/skipped/blocked counts, project and viewport evidence, coverage mode, and cleanup. `filtered` describes a selected scope; it is not full-suite evidence. The full-suite prerequisite metadata is advisory and does not schedule a rerun.
- Distinguish assertion failures from infrastructure blockers. For example, denied Sanity CDN assets or blocked SMTP are policy/dependency failures; preserve the failed HTTP assertion and report the dependency cause rather than bypassing policy or weakening TLS.
- Verify owned services stopped, task-created fixtures removed, generated session files and `.terra-cloud-auth-fixture.json` absent, and loopback ports closed. PGlite stops on wrapper exit. Keep test reports, credentials, sessions, and `work/` scratch out of commits.
