title: Add and configure a React error boundary
description: Choose a recovery region, provide an accessible fallback, and configure reset and reporting.
---

Use this guide when a client-rendered React region needs a local fallback after a descendant render failure. The boundary contains the failed UI region; the application still owns recovery, retry policy, and telemetry.

## Install and choose a recovery region

```sh
pnpm add @terra-symposium/standards-error-boundaries
```

Wrap a useful recovery unit, such as one report panel or route region. Keep independent content outside the boundary so one rendering failure does not remove working navigation or sibling panels.

## Render the fallback

The fallback should identify the user-facing problem and offer only an action the application can perform. Do not show raw exception text or a component stack.

```tsx
import { ErrorBoundary } from '@terra-symposium/standards-error-boundaries/react';

<ErrorBoundary
	name='Usage report'
	resetKey={workspaceId}
	onError={(error, context) => reportBoundaryError(error, context)}
	fallback={() => (
		<section role='alert' aria-labelledby='usage-error-title'>
			<h2 id='usage-error-title'>Usage data could not be shown</h2>
			<p>Your workspace and other reports are still available.</p>
			<button onClick={reloadUsage} type='button'>
				Retry this report
			</button>
		</section>
	)}
>
	<UsageReport workspaceId={workspaceId} />
</ErrorBoundary>;
```

## Choose reset behavior

The package clears its captured error when the configured reset input changes. Choose the reset trigger that matches the state the user can change.

||| [Reset when inputs change]

Pass a stable identity such as the selected account or workspace as `resetKey`. A new identity retries the child tree automatically.

||| [Explicit retry]

Have the fallback call an application action that changes the key or input passed to `resetKey`. The boundary does not retry a failed request or backing service on its own.

|||

## Props and exports

| Prop or export                                 | Contract                                                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `children`                                     | Descendant tree rendered until a failure is captured.                                                                     |
| `fallback`                                     | Optional function that returns application recovery UI. If omitted, the package renders a generic `role="alert"` message. |
| `name`                                         | Stable boundary name sent to `onError`; defaults to `Component`.                                                          |
| `onError`                                      | Receives the captured `Error` and React component stack from `componentDidCatch`.                                         |
| `resetKey`                                     | Changing this value clears the captured error and retries descendants.                                                    |
| `withErrorBoundary(Component, name, onError?)` | Higher-order wrapper that preserves component props and sets a useful display name.                                       |

The package root re-exports the React API. Prefer the explicit `/react` subpath in application components.

=== [What React does not catch] React boundaries catch descendant render, constructor, and lifecycle failures. React also documents errors thrown inside a `startTransition` action as boundary-caught. They do not catch ordinary event-handler exceptions, most asynchronous callbacks such as timers, server-rendering failures, errors in the boundary itself, or failures before React starts.

# Use normal `try`/`catch` and rejected-promise handling for imperative work. Add browser coverage for the user-visible fallback and verify that an independent sibling remains available.

:::note[Application-owned behavior]

Choose boundary size, fallback copy, retry limits, and telemetry destination in the application. The shared package contains the UI failure; it does not recover the underlying operation.

:::
