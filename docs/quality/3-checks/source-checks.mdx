This reference covers built-in checks that inspect source structure and user-interface code. For each check, the exact toggle, fix control, and supported behavior are listed beside its example.

## Source quality

### Document

Checks source documentation against the configured requirements.

**Toggle:** `enabledChecks.document` · **Command:** `document`

This check reports missing or incomplete documentation for an author to review. It does not create or rewrite comments, tags, headers, or section labels. Read the implementation and callers, then author each required description with implementation-specific context.

```json
{
	"documentation": {
		"required": { "types": true, "functions": true, "exportedFunctions": true, "noInlineFunctions": true }
	}
}
```

“Types” means classes, enums, interfaces, and type aliases. “Functions” means named function declarations. `exportedFunctions` can require only exported named functions when `functions` is false. `noInlineFunctions` reports arrow functions and function expressions and has no safe autofix. `maintain` remains a compatibility alias for `document`.

Write missing documentation after inspecting the declaration, implementation, and callers.

**Before** — the public function has no meaningful summary:

```ts
export function formatPrice(amount: number): string {
	return `$${amount.toFixed(2)}`;
}
```

**After** — a maintainer explains its intent and parameter:

```ts
/** Formats a price in US dollars with two decimal places.
 * @param amount Price in dollars.
 * @returns The formatted price.
 */
export function formatPrice(amount: number): string {
	return `$${amount.toFixed(2)}`;
}
```

### Format

Deterministic formatting through Prettier and canonical import layout.

**Toggle:** `enabledChecks.format` · **Fix:** `autofix.format` · **Command:** `format`

Runs Prettier on selected files and applies canonical layout protections, including configured handling of long one-line imports. Formatting changes presentation, preserves program meaning, and is separate from lint and semantic refactoring.

Configure `tools.prettier`, `prettierPrintWidth`, and `oneLineImports`. Prettier discovers its native configuration; this package does not install it. Install Prettier in the consuming repository with `pnpm add -D prettier`. For Astro files, also install `prettier-plugin-astro` and configure the plugin and `.astro` parser in `.prettierrc.mjs`; see [setup](/quality/0-getting-started/setup/) for an example.

**Before**

```ts
const result = { name: 'Terra', active: true };
```

**After** — Prettier applies the repository's configured layout:

```ts
const result = { name: 'Terra', active: true };
```

### Import validation

Resolve local imports using configured roots, extensions, and aliases.

**Toggle:** `enabledChecks.import` · **Fix:** none

Resolves relative and aliased imports in the configured source scope, including supported extensionless paths, index modules, and module forms. It reports unresolved local targets; there is no autofix because choosing a replacement requires semantic judgment.

Configure `sourceRoots`, `extensions`, `aliases`, and `externalPrefixes`. External prefixes mark intentionally external namespaces; aliases map import prefixes to repository paths. All matching files under configured roots are scanned.

**Before** — the relative target does not exist:

```ts
import { parseUser } from './users/parseUser.js';
```

**After** — point at the actual module (example repository layout: `src/user/parse-user.ts`):

```ts
import { parseUser } from '../user/parse-user.js';
```

### Name

Find naming drift and apply safe syntax-aware identifier renames.

**Toggle:** `enabledChecks.name` · **Fix:** `autofix.name`

Finds naming drift and safely renames whole words or prefixes after checking syntax, scope, collisions, protected paths, exports, shorthand properties, and JSX. Parameters in supported collection and event callbacks use one-letter initials (`member` becomes `m`, while a numeric `index` becomes `i`). Ambiguous or conflicting edits remain findings.

Use `protectedIdentifiers` for stable domain names, public vocabulary, and abbreviations. Export renaming is off by default; enable it with `renameExports`. `--warn` checks without renaming, and naming findings still fail the run. Review API-facing edits before accepting them.

**Before** — `command` is a configured long-word replacement:

```ts
const commandName = 'build';
run(commandName);
```

**After** — the safe rename updates the declaration and its references:

```ts
const cmdName = 'build';
run(cmdName);
```

### Accessibility

Opt in with `enabledChecks.accessibility: true`. The check inspects native JSX controls and elements with explicit interactive roles for a source-evident accessible name. It recognizes ARIA names, associated labels, static child text, and image alternatives. Fix mode copies a literal `title` to `aria-label` only when the element has no visible or uncertain content, and adds `aria-hidden="true"` to an unnamed inline SVG only when its parent control already has a clear name. It does not invent labels or alter keyboard behavior.

### React display names

Opt in with `enabledChecks.display-name: true`. The check finds direct named `forwardRef` components without a conventional `displayName`. Fix mode adds the component's own name only when the declaration and insertion point are unambiguous; existing custom assignments and wrapped components are left unchanged.

### Application error boundaries

The `error-boundaries` source check is mandatory and cannot be disabled. It checks React `createRoot()` and `hydrateRoot()` render roots for a top-level `@terra-symposium/standards-error-boundaries/react` boundary, and Astro configuration for the shared hydration integration. A normal fix-mode run can insert supported wrappers and configuration; `--warn` reports without writing. The focused command is `terra-quality error-boundaries --all`.

Static analysis verifies source shape, not runtime recovery. Use the application's browser suite to trigger a descendant render failure, assert the fallback, and confirm unrelated UI stays available. See the [React boundary API](/error-boundaries/1-react/react-boundaries/), [Astro hydration guide](/error-boundaries/2-frameworks/hydration/), and [Sanity Error Analysis dashboard](/error-boundaries/3-analytics/sanity-error-analysis/).

### Documented package commands

Opt in with `enabledChecks.documented-commands: true` and configure `documentation.commandRoots`. The check scans fenced `sh`, `bash`, `zsh`, or `shell` blocks for pnpm directory flags `-C` and `--prefix`. Fix mode changes those exact command forms to `--dir`; prose, other executables, and other code fences are preserved. This filesystem-only scan is cheap and can stay on the changed-file path when the configured roots are scoped to maintained documentation.

### Performance patterns

The opt-in `performancePatterns` check reports stable linear lookups such as `find`, `filter`, `includes`, `indexOf`, and `some` nested inside collection callbacks. It is advisory and never rewrites loops: use representative before/after measurements to decide whether precomputing an index preserves ordering, duplicate handling, and update semantics. Keep browser, broad integration, and benchmark validation in explicit or scheduled commands, and share expensive setup across cases in an existing suite.
