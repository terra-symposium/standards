Terra Quality separates source analysis from native tool and repository command execution. Use the map below to go directly to the check family; exact field names and defaults are in the [quality.json reference](/quality/2-configuration/quality-json/).

| Reference                                                           | Covers                                                                                         |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| [Source checks](/quality/3-checks/source-checks/)                   | Documentation, formatting, imports, naming, accessibility, boundaries, and performance checks. |
| [Refactoring checks](/quality/3-checks/refactoring-checks/)         | Forwarding, aliases, single-use declarations, and dead-code analysis.                          |
| [Repository pattern checks](/quality/3-checks/repository-patterns/) | Security, repeated classes, regex, Tailwind, and UI conventions.                               |
| [Tool and command checks](/quality/3-checks/tooling-checks/)        | ESLint, Knip, TypeScript, diff checks, configured commands, and recommendations.               |
| [Capability packages](/quality/1-packages/package-map/)             | The public API and CLI for each package.                                                       |

A typical run first selects source files, executes built-in checks, applies eligible fixes, then runs configured tools and commands in the aggregate runner's fixed phase order. The diagram shows that relationship at a high level.
