# npm package publishing

Terra releases use one central publisher in the Standards repository. Maintainers start a GitHub Actions run; they do not need to sign in to npm for each release. The workflow reads one credential from the Standards Actions secret PACKAGES_TOKEN. That credential must be an npm granular token with read and write access to the Terra Symposium packages.

## One publisher for Terra

The workflow at .github/workflows/publish-packages.yml is the single publisher. It builds and publishes the four Standards packages and @terra-symposium/docs. Keep the npm credential only in the Standards repository secret. Do not add per-repository tokens or copy it into consumer repositories.

The workflow checks out Docs at an explicit 40-character commit SHA, installs from its config lockfile, builds, and verifies the package name before publishing. Standards packages come from the checked-out Standards revision.

A credential can be valid in npm and still not be the value saved in GitHub. GitHub only shows when an Actions secret was updated; it cannot reveal the saved value. On November 10, 2026, the sole PACKAGES_TOKEN secret showed an update date of September 5, 2026, while npm showed the all-packages publish token was created November 1, 2026 and had never been used. That newer token therefore cannot be the value currently stored in PACKAGES_TOKEN. Replace the value of the existing secret with the intended token; do not create another GitHub secret or publisher.

The npm token page displays a token only when it is created. If its value was not saved, create one replacement with the required all-package access, update the same PACKAGES_TOKEN secret, verify a release, then revoke the superseded token. Never paste a token into source, an issue, a chat, a workflow file, or logs.

## Why npm OIDC is not one organization-wide publisher

npm Trusted Publishing uses short-lived GitHub OIDC credentials and avoids a stored npm token. npm requires a separate trusted-publisher configuration on each package, bound to a particular GitHub repository and workflow filename. It does not provide an organization-wide publisher connection. npm also requires a package's repository URL to match the GitHub repository publishing it. Terra packages are maintained in multiple repositories, so one OIDC configuration in Standards cannot publish all of them while preserving their source-repository links.

Therefore the one central publisher for the current multi-repository package set is the Standards workflow plus one all-packages credential. Switching to OIDC means configuring and validating each package against its own source repository workflow; that is a different publishing model, not one publisher with access to every package. Do not create additional OIDC connections as a workaround for a stale PACKAGES_TOKEN value.

npm's current account notice says tokens that bypass 2FA are being restricted for account changes from August 2026 and for direct publishing from January 2027. The existing publish token bypasses 2FA and expires January 30, 2027. Treat the single-token workflow as a temporary bridge. Before January 2027, choose a durable path: migrate to per-package OIDC publishers, or consolidate package source repositories and metadata so a single OIDC repository identity is truthful for every package. Do not promise that a bypass-2FA token will continue publishing after npm's announced cutoff.

## Release a package

1. Update the package version and release notes in its source repository, then merge the reviewed change.
2. For Docs, identify the full 40-character commit SHA. In the Standards Actions tab, run **Publish shared packages** with that SHA.
3. Confirm each expected package and version in the workflow output. The workflow skips versions already present on npm.
4. Verify the published version on npm, then update consumers and lockfiles.

The workflow does not accept a repository URL or arbitrary package name. Never overwrite or unpublish a release; publish a new version instead.

## Troubleshooting

| Symptom                    | Check                                                                                                                                                                                                                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ENEEDAUTH                  | Confirm the workflow references PACKAGES_TOKEN and that the Standards Actions secret is configured.                                                                                                                                                                                |
| Publish returns 403 or 404 | Check that the secret contains the current token and that the token has write access to every package. Compare token creation/rotation time with the secret's last-updated date. npm's 404 can also hide a failed publish authorization; it does not prove the package is missing. |
| Version already exists     | Verify that version on npm. Release a new version if further changes are needed.                                                                                                                                                                                                   |
| Docs checkout fails        | Supply a valid full 40-character commit SHA from Terra-Symposium/docs.                                                                                                                                                                                                             |
| Docs build fails           | Check the selected revision and the repository's config lockfile and build workflow.                                                                                                                                                                                               |

Keep the credential only in Standards Actions secrets. Rotate it through npm's account process and update the existing PACKAGES_TOKEN secret without exposing its value.
