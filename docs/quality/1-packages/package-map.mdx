`@terra-symposium/quality` contains the aggregate runner, shared core, reports, and focused checks. Import a subpath when an integration needs only one capability.

## Choose an entry point

||| [Aggregate workflow]

Use `@terra-symposium/quality` for the full schema, phase ordering, configured commands, progress, external-tool orchestration, compatibility APIs, combined reports, and development-port helpers.

|||

||| [Focused capability]

Import a capability subpath for its check family or public helper. All subpaths use the same `quality.json`.

|||

## Export references

Install `@terra-symposium/quality` once. Each subpath has a reference for its exports, CLI scope, and configuration.

| Export                                              | Responsibility                                                                               | CLI                                  |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------ |
| [Quality](/quality/1-packages/quality/)             | Aggregate schema, phase orchestration, compatibility APIs, commands, reports, and dev ports. | `terra-quality`, `terra-quality-dev` |
| [Core](/quality/1-packages/core/)                   | Shared configuration, source scope, analysis context, types, and CLI flags.                  | API only                             |
| [Documentation](/quality/1-packages/documentation/) | TSDoc/JSDoc, Doxygen, and documented commands.                                               | `terra-documentation`                |
| [Formatting](/quality/1-packages/formatting/)       | Source layout, safe structural transforms, and Prettier integration.                         | `terra-formatting`                   |
| [Imports](/quality/1-packages/imports/)             | Local import resolution and duplicate-import findings.                                       | `terra-imports`                      |
| [Languages](/quality/1-packages/languages/)         | Optional C, Java, and Python profiles.                                                       | `terra-language-checks`              |
| [Naming](/quality/1-packages/naming/)               | Naming and alias checks with safe rename helpers.                                            | `terra-naming`                       |
| [Patterns](/quality/1-packages/patterns/)           | Performance, repeated classes, regex, Tailwind, and UI patterns.                             | `terra-patterns`                     |
| [Reports](/quality/1-packages/reports/)             | GitHub/history reports and test-runner reporters.                                            | `terra-quality-reports`              |
| [Refactoring](/quality/1-packages/refactoring/)     | Forwarding, single-use, and dead-code analysis.                                              | `terra-refactoring`                  |
| [Security](/quality/1-packages/security/)           | Built-in repository source-security findings.                                                | `terra-security`                     |
| [UI](/quality/1-packages/ui/)                       | Accessibility, display names, boundaries, and UI recommendations.                            | `terra-ui-quality`                   |

=== [Package authoring boundary]

Core owns generic source scope and shared contracts. Focused checks keep their logic separate from the aggregate runner within the same package.

===

For rule enablement and autofix limits, read the [source check reference](/quality/3-checks/source-checks/) and [tool check reference](/quality/3-checks/tooling-checks/).
