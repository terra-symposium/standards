`@terra-symposium/standards-patterns` groups source-pattern checks that need repository context or a chosen policy. Some checks are advisory; a performance suggestion is not a benchmark result.

## Install and run

```sh
pnpm add -D @terra-symposium/standards-patterns
pnpm exec terra-patterns --all
```

`--all` scans the configured source roots. Use `--warn` to avoid any supported safe fixes while evaluating findings. The CLI uses the same config discovery and source scope as the aggregate runner.

## Check families

- `performancePatternFindings` finds linear collection searches nested inside collection callbacks. It recommends precomputing a `Map` or `Set`; it does not rewrite loops or fail the run because hot-path relevance and lookup semantics need measurement.
- `repeatedClassFindings`, `regexFindings`, and `uiPatternFindings` analyze configured repeated class strings, reusable regular expressions, and UI source patterns.
- `runTailwindCanonical` checks and can normalize the configured Tailwind canonical-class policy.

The API also exports fix and config types for supported pattern families. Each check has its own `enabledChecks` key and may require a corresponding settings object. See [built-in check reference](/quality/3-checks/check-reference/) and the [`quality.json` schema guide](/quality/2-configuration/quality-json/) before enabling a new policy.
