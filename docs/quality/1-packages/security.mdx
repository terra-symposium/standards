`@terra-symposium/standards-security` applies repository source-security policy using the shared Quality source scope. It complements code review, dependency analysis, secret scanning, runtime controls, and platform security features; it is not a security certification.

## Install and run

```sh
pnpm add -D @terra-symposium/standards-security
pnpm exec terra-security --all --warn
```

`--all` scans configured source roots and `--warn` guarantees a read-only run. The package loads the same root `quality.json` or `config/quality.json` as the other capabilities.

## Findings and controls

`securityFindings(cfg)` returns structured file and message findings. The built-in scanner checks configured forbidden terms and import specifiers, committed environment files, secret-shaped environment values referenced from client code, `dotenv` loading, and `process.env` access outside configured Node runtime roots. Scope comes from the Quality config and repository layout.

Set `security.runtimeRoots` to repository-relative files or directories containing Node-only server, tooling, or test code that owns environment access. The legacy `security.allowProcessEnvRoots` field remains accepted for existing configurations; migrate it to `runtimeRoots` when updating the shared package.

The scanner is source-based and pattern-based. It cannot establish whether a value is truly secret, discover every dynamic loader or alias, prove data flow through all runtime paths, or replace a dependency audit. Keep secret values out of reports, docs, test fixtures, and screenshots. See [the exact configuration fields](/quality/2-configuration/quality-json/) and [security/limits on built-in checks](/quality/3-checks/check-reference/).
