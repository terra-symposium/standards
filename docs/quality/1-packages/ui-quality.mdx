`@terra-symposium/standards-ui-quality` analyzes UI source for selected accessibility, component identity, error-boundary, and design-system policies. Its static findings do not prove accessibility or correct runtime recovery; test interactive behavior with assistive technology and browser scenarios as appropriate.

## Install and run

```sh
pnpm add -D @terra-symposium/standards-ui-quality
pnpm exec terra-ui-quality --all
```

The CLI uses shared Quality config and scope. `error-boundaries` is mandatory: Terra Quality checks React render roots for a top-level boundary and Astro configuration for the hydration integration, and this check cannot be disabled. `accessibility` and `display-name` remain opt-in through `enabledChecks`; `recommend` uses configured component rules. `--warn` is read-only and prevents the boundary fixer from writing changes.

## APIs

```ts
import { accessibilityFindings, displayNameFindings, errorBoundaryFindings, uiComponentRecommendations } from '@terra-symposium/standards-ui-quality';
```

The APIs cover accessible-name evidence and eligible literal fixes, missing display names on supported React patterns, unguarded client-rendered roots, and configured element-to-component recommendations. The package declares `@terra-symposium/standards-error-boundaries` as a peer dependency for its error-boundary source checks; install that runtime package when the application also needs the reusable boundary implementation.

The error-boundary library's React/Astro runtime behavior is documented in the [Error Boundaries section](/error-boundaries/1-react/react-boundaries/). See [configuration](/quality/2-configuration/quality-json/) for opt-in policy and [built-in checks](/quality/3-checks/check-reference/) for related patterns.
