title: Playwright evidence
description: Configure responsive projects, capture diagnostics and screenshots, and review reports.
---

`@terra-symposium/reporting` adds responsive projects and evidence to existing Playwright tests. The consumer owns scenarios, authentication, server setup, and data policy.

## Responsive projects

Wrap the existing config with `withResponsivePlaywright`:

```ts
import { defineConfig } from '@playwright/test';
import { withResponsivePlaywright } from '@terra-symposium/reporting/viewports';

export default withResponsivePlaywright(defineConfig({ projects: [{ name: 'chromium', testMatch: '**/*.spec.ts' }] }), { outputRoot: 'tests/results/visual' });
```

Regular projects expand across `mobile` (390 × 844), `sm` (640 × 800), `md` (768 × 900), `lg` (1024 × 768), `xl` (1280 × 720), and `2xl` (1536 × 864). Setup and dependency projects run once. Restrict a run with `PW_VIEWPORTS=mobile,lg pnpm exec playwright test`. Aliases include `phone`, `tablet`, `desktop` or `default`, and `wide`.

## Capture evidence

`diagnosticsTest` attaches console warnings and errors, uncaught page errors, and failed requests. `visualTest` adds named captures for multiple routes or states:

```ts
import { visualTest as test, expect } from '@terra-symposium/reporting/playwright';

test('account overview', async ({ page, visuals }) => {
	await page.goto('/account');
	await expect(page.getByRole('heading', { name: 'Account' })).toBeVisible();
	await visuals.capture('account-overview', { title: 'Account overview' });
});
```

Keep capture keys stable across viewports and unique within a test result. The default capture is a viewport JPEG; pass screenshot options to customize it. Review diagnostic URLs and messages for sensitive data before uploading artifacts.

## Review outputs

The reporter writes a workbook, copied screenshots, and keyed capture metadata under `tests/results/visual`. The default deck groups responsive screenshots by test. The workbook includes results, diagnostics, and enabled load timings.

For parallel viewport processes, share `TERRA_SCREENSHOT_RUN_ID`. Set `TERRA_SCREENSHOT_RUN_FINALIZE=0` for intermediate processes and `1` for the final process, which combines captures into one deck. Reuse the run ID after an interruption; matching test and viewport captures replace earlier images. See the [package API](/reporting/1-packages/reporting/) and [artifact reference](/reporting/4-artifacts/artifacts/).
