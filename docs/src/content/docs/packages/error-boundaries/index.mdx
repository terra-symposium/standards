title: Error boundaries
description: Catch React render failures and reuse small route-error helpers.

`@terra-symposium/error-boundaries` provides a React error boundary and wrapper, shared HTTP-status copy, and a helper for framework-provided Next.js error digests. It leaves fallback presentation, telemetry, and route behavior to the application.

## Install

The package expects React and React DOM `>=18` as peer dependencies:

```sh
pnpm add @terra-symposium/error-boundaries
```

## React boundary

Import from the package root or the explicit React entry point:

```tsx
import { ErrorBoundary } from '@terra-symposium/error-boundaries/react';

<ErrorBoundary
	name="Account panel"
	onError={(error, context) => {
		reportError(error, context);
	}}
	fallback={(error) => (
		<section role="alert">
			<h2>Account details are unavailable</h2>
			<button onClick={() => retryAccountLoad(error)}>Try again</button>
		</section>
	)}
	resetKey={accountId}
>
	<AccountPanel accountId={accountId} />
</ErrorBoundary>;
```

- `fallback` receives the caught error and returns the application's recovery UI. If omitted, the boundary renders a generic `role="alert"` message.
- `name` is included in the `onError` context; it defaults to `Component`.
- `onError` receives the `Error` and `{ name, componentStack }` for application-owned telemetry.
- Change `resetKey` when the application wants to clear a captured error and retry the child tree.
- `withErrorBoundary(Component, name, onError?)` returns a component wrapper that keeps the wrapped component's props.

React error boundaries catch errors in descendant constructors, lifecycle methods, and rendering. They do not catch event-handler errors, most asynchronous callbacks, server-rendering errors, or errors thrown by the boundary itself. See [React's error-boundary reference](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary) for the framework's full behavior.

## Status copy for Astro routes

The `/astro` entry point provides `ErrorStatus`, `ErrorStatusCopy`, `ERROR_STATUS_COPY`, and `errorStatusCopy(status)`. It supplies copy for status codes 400, 401, 403, 404, 500, 502, and 503; unknown values receive generic “Unknown Error” copy.

```astro
---
import { errorStatusCopy } from '@terra-symposium/error-boundaries/astro';

const copy = errorStatusCopy(Astro.response.status);
const { title, description } = copy;
---
<main>
	<h1>{title}</h1>
	<p>{description}</p>
</main>
```

Use the returned title and description in your Astro error page or response. The helper does not create a route, set a status code, or render a page.

## Next.js route-error helper

The `/next` entry point exports the `NextRouteError` and `NextRouteErrorProps` types and `errorDigest(error)`. The helper returns the framework's `digest` field without exposing the error message as an identifier.

```tsx
import { errorDigest } from '@terra-symposium/error-boundaries/next';
import type { NextRouteErrorProps } from '@terra-symposium/error-boundaries/next';

export default function ErrorPage({ error }: NextRouteErrorProps) {
	const digest = errorDigest(error);
	return <p role="alert">Reference: {digest ?? 'unavailable'}</p>;
}
```

## Entry points

| Import                                    | Exports                                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `@terra-symposium/error-boundaries`       | All React, status-copy, and Next.js helpers.                                                       |
| `@terra-symposium/error-boundaries/react` | `ErrorBoundary`, `ErrorBoundaryProps`, `ErrorBoundaryState`, `ErrorReporter`, `withErrorBoundary`. |
| `@terra-symposium/error-boundaries/astro` | `ErrorStatus`, `ErrorStatusCopy`, `ERROR_STATUS_COPY`, `errorStatusCopy`.                          |
| `@terra-symposium/error-boundaries/next`  | `NextRouteError`, `NextRouteErrorProps`, `errorDigest`.                                            |

The helpers do not replace application-specific fallback design, privacy-safe logging, route conventions, or deployment configuration.
