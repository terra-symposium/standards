## Requirements

Terra Quality supports Node.js `>=18.18` and is available from the public npm registry. The package does not install a formatter, linter, type checker, or repository build and test tools.

## Install

Add the package as a development dependency:

```sh
pnpm add -D @terra-symposium/standards-quality
```

Terra Quality coordinates repository tools but does not install or configure them. Install each tool you enable in `quality.json`. For example, formatting requires Prettier:

```sh
pnpm add -D prettier
```

For Astro files, install and register the Astro Prettier plugin:

```sh
pnpm add -D prettier-plugin-astro
```

```js
// .prettierrc.mjs
export default {
	plugins: ['prettier-plugin-astro'],
	overrides: [{ files: '*.astro', options: { parser: 'astro' } }],
};
```

Install ESLint, Knip, and TypeScript only when you enable their corresponding checks, and keep their project-specific rules in each tool's native configuration. Linting requires an ESLint flat config such as `eslint.config.mjs`.

Create `quality.json` at the repository root. This example enables built-in checks without requiring external tool installations:

```json
{
	"$schema": "./node_modules/@terra-symposium/standards-quality/quality.schema.json",
	"sourceRoots": ["src"],
	"extensions": [".js", ".jsx", ".ts", ".tsx"],
	"enabledChecks": {
		"format": false,
		"lint": false,
		"knip": false,
		"dead-code": false
	}
}
```

Add the tools you want and configure their native files before enabling those checks. For example, lint integration requires an ESLint flat config such as `eslint.config.mjs`; formatting uses Prettier's repository configuration when present.

## Run it

From the directory containing `quality.json`:

```sh
pnpm exec terra-quality
```

The default run selects changed and untracked source files from the Git worktree and applies enabled autofixes. Use a full read-only run for CI or review:

```sh
pnpm exec terra-quality quality --all --warn
```

Add `--skip-commands` when the repository's build and test commands run in another CI step. Add `--skip-recommendations` to omit advisory commands. See [CLI workflows](/packages/quality/workflows/) for the full mode table.

## React and TSX projects

Set the `jsx` option in the effective TypeScript project configuration. React projects generally use `react-jsx`:

```json
{
	"compilerOptions": {
		"jsx": "react-jsx"
	}
}
```

When a framework preset disables JSX for editor tooling, set a valid option in the repository's `tsconfig.json` and restart the TypeScript language server to clear stale diagnostics.

## Run lifecycle

1. The CLI loads `quality.json` from the current working directory.
2. It resolves `root`, discovers matching files under `sourceRoots`, and chooses changed/untracked files or the full set.
3. Enabled built-in checks inspect the selected sources. Configured tools and commands run from `root`.
4. In fix mode, enabled transformations and tool fixes can write changes. `--warn` disables these writes.

Common generated and dependency directories—including `.git`, `node_modules`, `dist`, `build`, `coverage`, `test-results`, `.next`, and `.astro`—are pruned from source discovery. Every matching file under configured source roots is checked.

The checker can identify source patterns and static issues, but it cannot prove runtime behavior, test coverage, application security, or the intent of framework conventions. Review changes that affect public APIs, persistence, authorization, or other domain boundaries.
