These checks need repository policy in `quality.json`. Findings reflect source patterns; they do not prove runtime security or design intent.

## Security

`enabledChecks.security` uses `security.forbiddenTerms`, `forbiddenImports`, `clientRoots`, and `runtimeRoots` to report environment files and loaders, secret-shaped client access, forbidden source, and `process.env` outside Node runtime paths. Findings fail Hygiene and have no autofix. `allowProcessEnvRoots` remains a compatibility alias for `runtimeRoots`. Keep secrets on the server and review each flagged boundary.

## Repeated classes and regex

| Check | Policy | Safe fix | Exclusions |
| --- | --- | --- | --- |
| `repeated-classes` | `repeatedClasses.minimumCount`, `extensions` | Extract repeated static file-local class strings into `CONFIG` or `CLASSES`. | Dynamic expressions and cross-file design decisions. |
| `regex-dedup` | `regexDedup.minimumCount`, `extensions`, `ignoredFiles` | Extract non-stateful file-local regex into `CONFIG` or `REGEX`. | Stateful flags and incompatible CommonJS consumers. |

Enable the checks with `enabledChecks.repeated-classes` or `enabledChecks.regex-dedup`; control writes with `autofix.repeatedClasses` and `autofix.regexDedup`. `regexDedup.sharedModule` supports cross-file ESM extraction when the repository provides a matching `.mjs` module and `.d.mts` declaration. Prefer a shared UI component when repeated classes represent a design primitive.

## UI patterns and recommendations

`enabledChecks.ui-patterns` reports strings listed in `uiPatterns.forbidden`; it does not rewrite UI. Keep the patterns specific to a known repository convention.

Run the separate, read-only recommendation report when reviewing native controls:

```sh
pnpm exec hygiene ui-recommendations --all
```

It scans `.astro`, `.jsx`, and `.tsx` and suggests shared `Button`, `Input`, or `ButtonLink` components when source evidence supports them. Plain anchors and primitive implementations under `components/ui` are excluded. Review every suggestion. `uiRecommendations.rules` replaces the default component names and imports; `types` restricts input types, and `when: "button-like"` or `"text-link"` restricts anchor matches. Explicit `variant` overrides inferred variants. `ignoredDirectories` excludes repository-owned primitive implementations.

## Tailwind canonical classes

For a Tailwind CSS v4 consumer, set `tailwindCanonical.stylesheet` and optional `sourceRoots`. Hygiene asks the installed design system for canonical class names and can apply exact replacements, such as `border-[var(--color-border)]` to `border-(--color-border)`.

```json
{ "tailwindCanonical": { "stylesheet": "src/styles/global.css", "sourceRoots": ["src"] } }
```

The normal Hygiene run includes this check. Use `hygiene tailwind-canonical --warn` for a read-only pass, `enabledChecks["tailwind-canonical"]: false` to disable it, or `autofix.tailwindCanonical: false` to retain findings without writes. The exported `runTailwindCanonical(cfg, fix?)` API is read-only by default. The check reports a skip if the installed Tailwind package lacks the required design-system API.
