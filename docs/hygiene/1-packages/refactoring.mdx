`@terra-symposium/hygiene/refactoring` contains source analysis for object forwarding and declarations that may be unused or have one consumer. It is designed to separate high-confidence edits from review-only suggestions.

## Install and run

```sh
pnpm add -D @terra-symposium/hygiene
pnpm exec refactoring --all
```

The CLI reads the shared Hygiene config and scope. `--warn` performs a read-only analysis; default fix mode can apply supported safe fixes. A finding may remain even when no automatic edit is offered.

## API and safety model

```ts
import { objectForwardingFindings, singleUseFindings, fixSingleUseDeclarations } from '@terra-symposium/hygiene/refactoring';
```

The package exports forwarding analysis, single-use type/declaration findings, fix helpers, and dead-code TypeScript-program utilities. Candidate dead-code edits are type-checked before write. Knip and ESLint consumers are also coordinated by the root runner. A declaration marked `// hygiene-ignore single-use -- <reason>` remains a review-only exception and its marker is itself validated; safe inline candidates are not suppressed by this directive.

Review edit diffs and run focused type checks after fixes. See the [aggregate dead-code workflow](/hygiene/1-packages/hygiene/) and [Hygiene troubleshooting](/hygiene/5-operations/troubleshooting/).
