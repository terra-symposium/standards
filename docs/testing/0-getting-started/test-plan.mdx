`@terra-symposium/testing` runs Standards-owned shared checks first, then the repository suites declared by its manifest. The plan makes suite order and file ownership explicit.

## Install and run

```sh
pnpm add -D @terra-symposium/testing
pnpm exec test-runner run --manifest config/tests.json
```

Use Node.js `>=20`. The runner validates file ownership before executing the ordered suites.

## Define the manifest

Use `config/tests.json` for new repositories. A suite has a stable name, one executable, optional argument strings, and repository-relative globs for the files it owns.

```json
{
	"version": 1,
	"suites": [
		{
			"name": "unit",
			"command": "pnpm",
			"args": ["run", "test:unit"],
			"owns": ["tests/unit/**/*.test.ts"]
		}
	]
}
```

The runner discovers files under `tests/` and names matching `*.test.*` or `*.spec.*`. It rejects legacy `test/` directories, invalid globs, duplicate suite invocations, overlapping ownership, and discovered test files that no suite owns. Update any script or template that recreates `test/` before running the plan.

## Select a run

|||[Full plan]

```sh
pnpm exec test-runner run --manifest config/tests.json
```

Runs shared checks followed by the ordered repository suites.

|||

|||[Shared checks only]

```sh
pnpm exec test-runner run --manifest config/tests.json --shared-only
```

Use this when a workflow intentionally separates test execution from plan validation.

|||

|||[Selected suites]

```sh
pnpm exec test-runner run --manifest config/tests.json --suites unit,contracts
```

Select named custom suites while retaining the shared checks.

|||

## Discovery and compatibility

The canonical path is `config/tests.json`. If it is absent, the runner recognizes `tests/tests.json` and the legacy root `.tests.json`. Pass `--manifest PATH` to select another location.

===[When tests move]

Map each moved or retired test to its new owner. Update the `owns` globs in the same change. Keep a retired assertion only when its behavior is covered elsewhere or the coverage gap is explicitly accepted.

Place tests near the module or route they prove. Use unit/contract suites for isolated behavior, integration suites for composed services, and browser suites for visible interactions. Exclude fixture-only files from ownership globs when they are not test cases.
